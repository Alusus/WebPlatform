## نظرة عامة

مقابس الويب في مـنصة_ويب مطبقة في نصفين مستقلين يعكس كل منهما الآخر:

* **`مـسار_مقبس_ويب` (`WsRoute`)** — منفذ جانب الخادم. يُنشأ نموذج منه لكل اتصال عميل يصل إلى المسار
  الذي تحدده، ويبقى حيًّا طوال مدة ذلك الاتصال.
* **`عـميل_مقبس_ويب` (`WsClient`)** — عميل جانب المتصفح، وهو غلاف رقيق حول كائن `WebSocket` الأصلي
  في المتصفح. اقرأ أولًا توثيق
  [واجهة WebSocket في MDN](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket) لفهم الكائن
  الذي يغلّفه هذا الصنف.

عادةً ما تستخدم الاثنين معًا: منفذ `مـسار_مقبس_ويب` على الخادم، وعميل `عـميل_مقبس_ويب` يتصل به من
صفحة `منفذ_مرئي` (`uiEndpoint`) على الواجهة.

## جانب الخادم: مـسار_مقبس_ويب (WsRoute)

### إنشاء منفذ مـسار_مقبس_ويب

يمكنك إنشاء منفذ مقبس بكتابة صنف عادي، وإضافة المبدل `مسار_مقبس` (`wsRoute`) له مع تحديد المسار الذي
سيستمع عليه، ثم حقن `مـسار_مقبس_ويب` (`WsRoute`) فيه باستخدام المبدل `@حقنة`.

```
@مسار_مقبس["/chat"]
صنف مـقبس_الدردشة {
    @حقنة عرف اتصال_مقبس: مـسار_مقبس_ويب؛
}
```

<div dir=ltr>

```
@wsRoute["/chat"]
class ChatSocket {
    @injection def wsRoute: WsRoute;
}
```

</div>

الآن أصبح لديك منفذ مقبس يستمع على `/chat`. يُنشأ نموذج جديد من `مـقبس_الدردشة` لكل اتصال عميل،
ويبقى حيًّا طوال مدة ذلك الاتصال.

### المهل الزمنية (Timeouts)

عند بدء الخادم (`شغل_الخادم`، `ابدأ_الخادم`، `ابن_وشغل_الخادم`، إلخ)، يمكنك تجاوز القيمة المبدئية
لـ`websocket_timeout_ms` عبر المعطى `الخيارات: مـصفوفة[مـؤشر_محارف]`. يتحكم هذا الخيار في المدة التي
يمكن أن يبقى فيها اتصال `مـسار_مقبس_ويب` دون استجابة قبل أن يعتبره الخادم غير مستجيب ويغلقه. قيمته
المبدئية `10000` (10 ثوانٍ) إن لم تحددها بنفسك.

```
شغل_الخادم[وحدات_الخادم](
    مسار_الموارد_الرئيسي، مسار_المنافذ_المرئية،
    مـصفوفة[مـؤشر_محارف]({ "listening_ports"، "8010"، "websocket_timeout_ms"، "30000" })
)؛
```

<div dir=ltr>

```
runServer[serverModules](
    mainAssetsPath, uiEndpointsPath,
    Array[CharsPtr]({ "listening_ports", "8010", "websocket_timeout_ms", "30000" })
);
```

</div>

لا تُغيّر هذه القيمة بشكل عشوائي — اختبرها أولًا مقابل الحمل المتوقع لتطبيقك قبل الاعتماد على قيمة
مختلفة في الإنتاج.

يُفعّل الخادم أيضًا معالجة CivetWeb المدمجة لإطارات ping/pong في كل اتصالات المقبس: فيرد تلقائيًا على
إطارات PING الواردة من العميل بإطارات PONG، ويُصفّي إطارات PONG قبل أن تصل إلى `عند_استلام_بيانات`
(`onData`)، لذا لست بحاجة للتعامل معها بنفسك أبدًا.

### تخصيص المعالجات

يمنحك `مـسار_مقبس_ويب` أربعة معالجات يمكنك تخصيصها للتفاعل مع دورة حياة الاتصال:

* `عند_الاتصال` (`onConnect`): يُستدعى عندما يبدأ العميل المصافحة لإنشاء اتصال. في هذه اللحظة يكون
  `هذا.الاتصال` (`this.connection`، وهو مؤشر خام `مؤشر[بـننف.اتـصال]`) قد أُسند بالفعل، لذا يمكنك
  استخدامه لفحص طلب المصافحة (الترويسات، سلسلة الاستعلام، إلخ) عبر
  `بـننف.هات_معلومات_الطلب(هذا.الاتصال)`. أرجع `0` لقبول الاتصال، أو `1` لرفضه.

* `عند_الجهوزية` (`onReady`): يُستدعى بعد انتهاء المصافحة وفتح الاتصال. هذه أول نقطة يمكنك فيها إرسال
  البيانات.

* `عند_استلام_بيانات` (`onData`): يُستدعى مرة واحدة لكل رسالة كاملة (نصية أو ثنائية)، بعد إعادة تجميع
  أي تجزئة عبر عدة إطارات داخليًا. تُمرَّر بايتات الرسالة كـ `بيانات: سند[مـصفوفة[مـحرف]]`
  (`data: ref[Array[Char]]`).

* `عند_الإغلاق` (`onClose`): يُستدعى بعد إغلاق الاتصال.

بما أن هذه المعالجات موجودة على `مـسار_مقبس_ويب` المحقون، فإنك تخصصها بهذه الصيغة، مطابقةً التوقيع
الأصلي تمامًا:

```
عملية (هذا: مـسار_مقبس_ويب).عند_الاتصال() : صـحيح حدد_مؤشر {
    مـتم.طـرفية.اطبع("طريقة الطلب: %s\ج"، بـننف.هات_معلومات_الطلب(هذا.الاتصال)~محتوى.طريقة_الطلب)؛
    مـتم.طـرفية.اطبع("لدينا اتصال جديد الآن\ج")؛
    أرجع 0؛
}
```

<div dir=ltr>

```
handler (this: WsRoute).onConnect() : Int set_ptr {
    Console.print("request method: %s\n", Http.getRequestInfo(this.connection)~cnt.requestMethod);
    Console.print("we have new connection now\n");
    return 0;
}
```

</div>

يخبر `(هذا: مـسار_مقبس_ويب)` المترجم أنك تقدّم تنفيذًا لأحد معالجات `مـسار_مقبس_ويب`، بينما تقوم
`حدد_مؤشر` (`set_ptr`) بتثبيته كالمعالج المستخدم لهذا الصنف بدلًا من المعالج المبدئي. لست مضطرًا
لتخصيص المعالجات الأربعة كلها — أي معالج تتجاهله يُبقي على سلوك `مـسار_مقبس_ويب` المبدئي.

نجمع كل ذلك معًا:

```
@مسار_مقبس["/chat"]
صنف مـقبس_الدردشة {
    @حقنة عرف اتصال_مقبس: مـسار_مقبس_ويب؛

    عملية (هذا: مـسار_مقبس_ويب).عند_الاتصال() : صـحيح حدد_مؤشر {
        مـتم.طـرفية.اطبع("طريقة الطلب: %s\ج"، بـننف.هات_معلومات_الطلب(هذا.الاتصال)~محتوى.طريقة_الطلب)؛
        مـتم.طـرفية.اطبع("لدينا اتصال جديد الآن\ج")؛
        أرجع 0؛
    }

    عملية (هذا: مـسار_مقبس_ويب).عند_الجهوزية() : فـراغ حدد_مؤشر {
        هذا.أرسل_نصا("مرحبا!")؛
        مـتم.طـرفية.اطبع("المقبس جاهز الآن\ج")؛
    }

    عملية (هذا: مـسار_مقبس_ويب).عند_استلام_بيانات(بيانات: سند[مـصفوفة[مـحرف]]، ثنائي: ثـنائي) : فـراغ حدد_مؤشر {
        مـتم.طـرفية.اطبع("استلمنا هذه البيانات: %s\ج"، بيانات.صوان)؛
    }

    عملية (هذا: مـسار_مقبس_ويب).عند_الإغلاق() : فـراغ حدد_مؤشر {
        مـتم.طـرفية.اطبع("تم إغلاق الاتصال\ج")؛
    }
}
```

<div dir=ltr>

```
@wsRoute["/chat"]
class ChatSocket {
    @injection def wsRoute: WsRoute;

    handler (this: WsRoute).onConnect() : Int set_ptr {
        Console.print("request method: %s\n", Http.getRequestInfo(this.connection)~cnt.requestMethod);
        Console.print("we have new connection now\n");
        return 0;
    }

    handler (this: WsRoute).onReady() : Void set_ptr {
        this.sendText("hello!");
        Console.print("the socket is ready now\n");
    }

    handler (this: WsRoute).onData(data: ref[Array[Char]], isBinary: Bool) : Void set_ptr {
        Console.print("we received this data: %s\n", data.buf);
    }

    handler (this: WsRoute).onClose() : Void set_ptr {
        Console.print("connection closed\n");
    }
}
```

</div>

### بيانات مخصصة

يمكنك وضع بيانات مخصصة على الصنف، كمعرّف خاص بكل اتصال يصل إلى ذلك المنفذ:

```

صنف مـقبس_الدردشة {

    عرف معرف: صـحيح؛

    عملية (هذا: مـسار_مقبس_ويب).عند_الاتصال() : صـحيح حدد_مؤشر {

        أرجع 0؛

    عملية (هذا: مـسار_مقبس_ويب).عند_الإغلاق() : فـراغ حدد_مؤشر {
        مـتم.طـرفية.اطبع("تم إغلاق الاتصال ذي المعرف %i\ج"، هذا.معرف)؛
    }
}
```

### مرجع مـسار_مقبس_ويب (WsRoute)

هذا هو الصنف الذي تحقنه في الصنف الذي تنشئه بالمبدل `مسار_مقبس`، ويمثل اتصال مقبس واحد. نموذج منه
(عبر صنفك) هو ما تشير إليه `هذا` (`this`) داخل كل معالج تخصصه.

يمكن أن يكون في إحدى الحالات التالية، معبّرًا عنها بقيم `حـالة_مسار_مقبس_ويب` (`WsRouteStatus`):

* `حـالة_مسار_مقبس_ويب._قيد_الاتصال_` (`WsRouteStatus.CONNECTING`): الحالة المبدئية، حتى تنتهي
  المصافحة.

* `حـالة_مسار_مقبس_ويب._مفتوح_` (`WsRouteStatus.OPENED`): الحالة الوحيدة التي يمكنك فيها إرسال
  واستقبال إطارات البيانات؛ كما يمكنك إغلاق الاتصال أثناءها.

* `حـالة_مسار_مقبس_ويب._قيد_الإغلاق_` (`WsRouteStatus.CLOSING`): الحالة بين استدعاء `أغلق` (`close`)
  واستدعاء المعالج `عند_الإغلاق` (`onClose`).

* `حـالة_مسار_مقبس_ويب._مغلق_` (`WsRouteStatus.CLOSED`): الحالة النهائية، وتعني أن الاتصال مغلق.

#### هات_الحالة (getStatus)

```
عملية هذا.هات_الحالة(): حـالة_مسار_مقبس_ويب؛
```

```

```

</div>

`حـالة_مسار_مقبس_ويب._مفتوح_`.

#### أرسل_ثنائيا (sendBinary)


* `طول_البيانات` (`dataLen`): طول `بيانات` (`data`) بالبايتات.

#### أغلق (close)


يُغلق الاتصال: ينقل الحالة إلى `حـالة_مسار_مقبس_ويب._قيد_الإغلاق_`، ويرسل إطار إغلاق للعميل؛ ويُستدعى
`عند_الإغلاق` بمجرد اكتمال مصافحة الإغلاق.

* الصيغة بلا معطيات تُغلق الاتصال برمز حالة `1000` (إغلاق عادي) ودون رسالة سبب.
* الصيغة الثانية تتيح لك تحديد رمز حالة ورسالة سبب. يجب أن تكون الرموز الخاصة بالتطبيق ضمن المجال
  `4000` إلى `4999` — راجع
  [مواصفة RFC 6455 لرموز الحالة](https://datatracker.ietf.org/doc/html/rfc6455#section-7.4.2).

## جانب المتصفح: عـميل_مقبس_ويب (WsClient)

### إنشاء اتصال

يمكن استخدام `عـميل_مقبس_ويب` كقيمة عادية — أنشئه ثم استدعِ `اتصل` (`connect`):

```
عرف مقبس: عـميل_مقبس_ويب؛
إذا ليس مقبس.اتصل("ws://localhost:8070/chat") {
    // فشلت محاولة الاتصال حتى قبل أن تبدأ (رابط غير صالح، مخطط غير صالح،
    // بروتوكولات مشوهة، رابط يحتوي على جزء (fragment)، إلخ)
}
```

<div dir=ltr>

```
def ws: WsClient;
if not ws.connect("ws://localhost:8070/chat") {
    // the connection attempt couldn't even start (bad URL, bad scheme, malformed
    // protocols, a URL containing a fragment, etc.)
}
```

</div>

```
عملية هذا.اتصل(الرابط: مـؤشر_محارف): ثـنائي؛
عملية هذا.اتصل(الرابط: مـؤشر_محارف، البروتوكولات: مـؤشر_محارف): ثـنائي؛
```

<div dir=ltr>

```
handler this.connect(url: CharsPtr): Bool;
handler this.connect(url: CharsPtr, protocols: CharsPtr): Bool;
```

</div>

تتيح لك `البروتوكولات` (`protocols`) عرض بروتوكولات فرعية، تمامًا كالمعطى الثاني لبانِي `WebSocket` في
المتصفح. راجع
[MDN](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/WebSocket#exceptions) للاطلاع على
القائمة الكاملة لحالات فشل الإنشاء المتزامن — وهذا ما يجعل `اتصل` (`connect`) يُرجع `خطأ` (`false`).
استدعاء `اتصل` مجددًا أثناء وجود اتصال قائم بالفعل لا يفعل شيئًا ويُرجع `صح` (`true`).

إرجاع `صح` (`true`) يعني فقط أن محاولة الاتصال قد بدأت — و هذا **لا** يعني أن الاتصال أصبح مفتوحًا
بعد. انتظر حدث/منادى الفتح لذلك.

إن كنت تفضّل الحصول على مرجع مخصص على الكومة وقابل للمشاركة بدلًا من قيمة عادية، فإن `أنشئ` (`create`)
دالة مساعدة تُنشئ `عـميل_مقبس_ويب` وتتصل به مباشرة:

```
دالة أنشئ(الرابط: مـؤشر_محارف، البروتوكولات: مـؤشر_محارف): سـندنا[عـميل_مقبس_ويب]؛
دالة أنشئ(الرابط: مـؤشر_محارف): سـندنا[عـميل_مقبس_ويب]؛
```

<div dir=ltr>

```
func create(url: CharsPtr, protocols: CharsPtr): SrdRef[WsClient];
func create(url: CharsPtr): SrdRef[WsClient];
```

</div>

```
عرف مقبس: سـندنا[عـميل_مقبس_ويب] = عـميل_مقبس_ويب.أنشئ("ws://localhost:8060/echo")؛
إذا مقبس.أهو_عدم() {
    // رابط أو بروتوكولات غير صالحة - لم يبدأ الاتصال
}
```

<div dir=ltr>

```
def ws: SrdRef[WsClient] = WsClient.create("ws://localhost:8060/echo");
if ws.isNull() {
    // bad URL/protocols - the connection never started
}
```

</div>

تُرجع `أنشئ` (`create`) `سـندنا[عـميل_مقبس_ويب]` خاليًا (`isNull() == true`) إذا تعذّر بدء محاولة
الاتصال، حتى لا تنتهي بامتلاك نموذج معطوب.

#### متصل (connected)

```
عرف متصل: ثـنائي = خطأ؛
```

<div dir=ltr>

```
def connected: Bool = false;
```

</div>

قيمته `صح` (`true`) طوال مدة فتح الاتصال (من حدث/منادى الفتح إلى حدث/منادى الإغلاق). تحقق منه قبل
إرسال البيانات إن لم تكن متأكدًا من حالة الاتصال الحالية.

### الأحداث

يعرض `عـميل_مقبس_ويب` أربعة حقول منادى (callback) تُسند إليها `مغلفة` (`closure`):

```
عرف منادى_الفتح: مغلفة()؛
عرف منادى_الرسالة: مغلفة(سند[بـيانات_رسالة_مقبس])؛
عرف منادى_الخطأ: مغلفة()؛
عرف منادى_الإغلاق: مغلفة(سند[بـيانات_إغلاق_مقبس])؛
```

<div dir=ltr>

```
def openCallback: closure();
def messageCallback: closure(ref[WsMessageInfo]);
def errorCallback: closure();
def closeCallback: closure(ref[WsCloseInfo]);
```

</div>

```
مقبس.منادى_الفتح = مغلفة () {
    مـتم.طـرفية.اطبع("تم الاتصال!\ج")؛
}؛
مقبس.منادى_الرسالة = مغلفة (معلومات: سند[بـيانات_رسالة_مقبس]) {
    مـتم.طـرفية.اطبع("استُلم: %s\ج"، معلومات.البيانات_النصية.صوان)؛
}؛
مقبس.منادى_الخطأ = مغلفة () {
    مـتم.طـرفية.اطبع("حدث خطأ على مستوى الاتصال\ج")؛
}؛
مقبس.منادى_الإغلاق = مغلفة (معلومات: سند[بـيانات_إغلاق_مقبس]) {
    مـتم.طـرفية.اطبع("أُغلق برمز %i: %s\ج"، معلومات.الرمز، معلومات.السبب.صوان)؛
}؛
```

<div dir=ltr>

```
ws.openCallback = closure () {
    Console.print("connected!\n");
};
ws.messageCallback = closure (info: ref[WsMessageInfo]) {
    Console.print("received: %s\n", info.strData.buf);
};
ws.errorCallback = closure () {
    Console.print("a connection-level error occurred\n");
};
ws.closeCallback = closure (info: ref[WsCloseInfo]) {
    Console.print("closed with code %i: %s\n", info.code, info.reason.buf);
};
```

</div>

تُستدعى هذه داخليًا من أربعة معالجات فعلية — `عند_الفتح`، `عند_استلام_رسالة`، `عند_الخطأ`،
`عند_الإغلاق` (`onOpen`, `onMessage`, `onError`, `onClose`) — يستدعي كل منها المنادى المقابل إن كان
مُسندًا. إن كنت تفضّل اشتقاق صنف من `عـميل_مقبس_ويب` بدلًا من إسناد المغلفات، يمكنك تخصيص هذه
المعالجات مباشرةً بنفس الطريقة التي تخصص بها معالجات `مـسار_مقبس_ويب`.

#### عند_الفتح / منادى_الفتح (onOpen / openCallback)

يُطلق بمجرد إنشاء الاتصال. راجع
[MDN](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/open_event) لمعرفة متى يُطلق هذا
الحدث بالضبط.

#### عند_استلام_رسالة / منادى_الرسالة (onMessage / messageCallback)

يُطلق مرة واحدة لكل رسالة مستلمة. الحمولة هي `بـيانات_رسالة_مقبس` (`WsMessageInfo`):

```
صنف بـيانات_رسالة_مقبس {
    عرف أهو_رقمي: ثـنائي؛
    عرف البيانات_الرقمية: مؤشر[مصفوفة[طـبيعي[8]]]؛
    عرف طول_البيانات_الرقمية: صـحيح_متكيف؛
    عرف البيانات_النصية: نـص؛
}
```

<div dir=ltr>

```
class WsMessageInfo {
    def isBinary: Bool;
    def binaryData: ptr[array[Word[8]]];
    def binaryDataLength: ArchInt;
    def strData: String;
}
```

</div>

* `أهو_رقمي` (`isBinary`): `صح` إن أُرسلت الرسالة كبيانات ثنائية، `خطأ` إن أُرسلت كنص.
* `البيانات_النصية` (`strData`): نص الرسالة. له معنى فقط عندما تكون `أهو_رقمي` بقيمة `خطأ`.
* `البيانات_الرقمية` / `طول_البيانات_الرقمية` (`binaryData` / `binaryDataLength`): البايتات الخام
  وطولها. لهما معنى فقط عندما تكون `أهو_رقمي` بقيمة `صح`.

راجع [MDN](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/message_event) لمعرفة متى
يُطلق هذا الحدث بالضبط.

#### عند_الخطأ / منادى_الخطأ (onError / errorCallback)

يُطلق عند حدوث خطأ حقيقي على مستوى الاتصال. راجع
[MDN](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/error_event) لمعرفة متى يُطلق هذا
الحدث بالضبط.

#### عند_الإغلاق / منادى_الإغلاق (onClose / closeCallback)

يُطلق بمجرد إغلاق الاتصال بشكل كامل، سواء بدأه الطرف المحلي أو الخادم. الحمولة هي `بـيانات_إغلاق_مقبس`
(`WsCloseInfo`):

```
صنف بـيانات_إغلاق_مقبس {
    عرف الرمز: صـحيح؛
    عرف السبب: نـص؛
    عرف إغلاق_مقصود: ثـنائي؛
}
```

<div dir=ltr>

```
class WsCloseInfo {
    def code: Int;
    def reason: String;
    def wasClean: Bool;
}
```

</div>

* `الرمز` (`code`): رمز إغلاق المقبس.
* `السبب` (`reason`): نص سبب الإغلاق، إن وُجد.
* `إغلاق_مقصود` (`wasClean`): فيما إذا اكتملت مصافحة الإغلاق بشكل نظيف.

راجع [MDN](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/close_event) لمعرفة متى يُطلق
هذا الحدث بالضبط. بحلول وقت إطلاقه تكون موارد الاتصال قد حُررت بالفعل — تصبح `متصل` بقيمة `خطأ` ولم
تعد دوال الحالة أدناه صالحة (راجع [الحالة](#الحالة-state)).

### إرسال البيانات

```
عملية هذا.أرسل_نصا(بيانات: مـؤشر_محارف): مـؤشر_محارف؛
عملية هذا.أرسل_ثنائيا(بيانات: مـؤشر_محارف، طول_البيانات: طـبيعي_متكيف): مـؤشر_محارف؛
```

<div dir=ltr>

```
handler this.sendText(data: CharsPtr): CharsPtr;
handler this.sendBinary(data: CharsPtr, dataLen: ArchWord): CharsPtr;
```

</div>

يُرسل الأول رسالة نصية، ويُرسل الثاني `طول_البيانات` (`dataLen`) بايتات خامة بدءًا من `بيانات`
(`data`). يُرجع كلاهما مؤشرًا خاليًا إن لم يرمِ المتصفح استثناءً، أو مؤشرًا لرسالة الخطأ إن رُمي
استثناء.

راجع [MDN](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/send#exceptions) لمعرفة متى
يُرمى الاستثناء الأصلي بالضبط.

### إغلاق الاتصال

```
عملية هذا.أغلق(): مـؤشر_محارف؛
عملية هذا.أغلق(الرمز: صـحيح): مـؤشر_محارف؛
عملية هذا.أغلق(الرمز: صـحيح، السبب: مـؤشر_محارف): مـؤشر_محارف؛
```

<div dir=ltr>

```
handler this.close(): CharsPtr;
handler this.close(code: Int): CharsPtr;
handler this.close(code: Int, reason: CharsPtr): CharsPtr;
```

</div>

يُغلق الاتصال. الصيغة بلا معطيات تستخدم الرمز `1000` (إغلاق عادي) دون سبب؛ بينما تتيح لك الصيغتان
الأخريان تحديد رمز و/أو سبب. نفس صيغة الإرجاع المستخدمة في `أرسل_نصا`.

راجع [MDN](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/close#exceptions) لمعرفة متى
يُرمى الاستثناء الأصلي بالضبط.

### الحالة

```
عملية هذا.هات_الحالة(): صـحيح؛
عملية هذا.هات_الرابط(): مـؤشر_محارف؛
عملية هذا.هات_البروتوكول(): مـؤشر_محارف؛
عملية هذا.هات_الامتدادات(): مـؤشر_محارف؛
عملية هذا.هات_الكمية_المخزنة(): طـبيعي_متكيف؛
```

<div dir=ltr>

```
handler this.getState(): Int;
handler this.getUrl(): CharsPtr;
handler this.getProtocol(): CharsPtr;
handler this.getExtensions(): CharsPtr;
handler this.getBufferedAmount(): ArchWord;
```

</div>

تُرجع هذه الدوال الخاصية المقابلة من [كائن WebSocket في
المتصفح](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket): تُرجع `هات_الحالة` خاصية
[`readyState`](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/readyState)، وتُرجع
`هات_الرابط` خاصية [`url`](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/url)، وتُرجع
`هات_البروتوكول` خاصية
[`protocol`](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/protocol)، وتُرجع
`هات_الامتدادات` خاصية
[`extensions`](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/extensions)، وتُرجع
`هات_الكمية_المخزنة` خاصية
[`bufferedAmount`](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/bufferedAmount).

بمجرد أن يُغلق الاتصال فعليًا (يُطلق حدث/منادى الإغلاق)، تحرّر المكتبة تتبعها للكائن الأصلي في المتصفح
تلقائيًا. لا تستدعِ هذه الدوال بعد إطلاق `عند_الإغلاق` / `منادى_الإغلاق` — بل اقرأ ما تحتاجه من حمولة
`بـيانات_إغلاق_مقبس` بدلًا من ذلك.

### دورة الحياة

تدمير `عـميل_مقبس_ويب` (سواء بخروجه من النطاق، أو إعادة تعيينه، أو استدعاء `.release()` على
`سـندنا[عـميل_مقبس_ويب]`) لا يفعل سوى إيقاف تتبع المكتبة للاتصال — و**لا** يُرسل إطار إغلاق نيابةً
عنك. استدعِ `أغلق` بنفسك أولًا إن أردت أن يُغلَق الاتصال بشكل نظيف قبل تحرير الكائن.

## تجميع كل ذلك معًا

منفذ بأسلوب دردشة بسيط، مقترن بعميل متصفح يعيد الاتصال بتأخير تصاعدي عند انقطاع غير نظيف:

```
@مسار_مقبس["/chat"]
صنف مـقبس_الدردشة {
    @حقنة عرف اتصال_مقبس: مـسار_مقبس_ويب؛

    عملية (هذا: مـسار_مقبس_ويب).عند_استلام_بيانات(بيانات: سند[مـصفوفة[مـحرف]]، ثنائي: ثـنائي) : فـراغ حدد_مؤشر {
        إذا ثنائي أرجع؛
        هذا.أرسل_نصا(بيانات.صوان)؛
    }
}
```

```
@wsRoute["/chat"]
class ChatSocket {
    @injection def wsRoute: WsRoute;

    handler (this: WsRoute).onData(data: ref[Array[Char]], isBinary: Bool) : Void set_ptr {
        if isBinary return;
        this.sendText(data.buf);
    }
}
```
